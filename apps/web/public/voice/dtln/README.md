# Browser denoiser provenance

`dtln.js` is the realtime voice denoiser the web app loads into an
`AudioWorklet` (`processor.js`). It is a compiled third-party component:
[DataDog/dtln-rs](https://github.com/DataDog/dtln-rs) — DTLN noise suppression
written in Rust, linked against TensorFlow Lite, with two quantized models
embedded — compiled to WebAssembly with Emscripten and inlined into the
generated JavaScript glue as a single file. Ficus owns `processor.js` and the
small wrapper additions described below; the binary is upstream's work and
this directory carries its notices.

## Exactly what is shipped

`provenance.json` describes the file in this directory: SHA-256 of `dtln.js`,
SHA-256 and size of the WebAssembly binary embedded in it, the upstream commit
it was built from and the toolchain that built it. It is regenerated by the
build and checked against the shipped file by
`apps/web/src/voice/dtlnProvenance.test.ts`, so it cannot drift from the asset.

The build recipe is `apps/web/scripts/dtln/` (a Dockerfile plus `build.sh`):

- source: `DataDog/dtln-rs` at the commit pinned in the Dockerfile
  (`DTLN_RS_COMMIT`), cloned fresh for every build;
- toolchain: the pinned `emscripten/emsdk` image and Rust toolchain named in
  the Dockerfile, target `wasm32-unknown-emscripten`, `cargo build --release --locked`;
- inputs from that commit: the Rust crate, `model/model_quant_{1,2}.tflite`
  (embedded with `include_bytes!`), and `tflite/tflite-prebuilt.wasm.tar.bz2`,
  upstream's prebuilt TensorFlow Lite static libraries for WebAssembly;
- three files overlaid on the checkout, each commented with why: `build.rs`
  (upstream's only defines `main` for macOS/Windows build hosts),
  `config.toml` (an Emscripten link flag whose quoted form emcc 4 rejects) and
  `dtln_post.js` (Ficus's wrapper: a `ready` getter, a `postRun` array, and
  reading the heap through the module-scope `HEAPF32` view);
- after the link, `build.sh` appends `export default DtlnPlugin` so the glue is
  an ES module, and formats it with the repository's prettier config.

`reproducibleBuildVerified` in `provenance.json` is set only when
`NO_CACHE=1 build.sh --check` — a second build from a cold Docker cache —
produced a byte-identical file. Rebuild and reinstall with
`bash apps/web/scripts/dtln/build.sh`; bump the `?v=` cache-buster in
`processor.js` and `apps/web/src/voice/realtimeTransport.ts` when you do.

What this does not claim: the TensorFlow Lite libraries are consumed as the
prebuilt archive upstream committed; their own build (TensorFlow version and
flags) is not reproduced here. The component inventory below is what that
archive contains.

- `LICENSE-3rdparty.csv` lists `wav` (LGPL-3.0). It is used only by upstream's

  Node native module; in the wasm they contribute only stub symbols.
- The two `.tflite` models are files in the upstream repository and are
  covered by its MIT license. Their training data and recipe are not published
  by upstream.

## History

The asset first arrived in Ficus (May 2026) as a prebuilt file with no recorded
build, and was carried with reference notices only. It was replaced in
September 2026 by the pinned, reproducible build described above; the WASM
hash changed with it (the earlier binary was from an unknown Emscripten 3.1.x
build of what was very probably the same upstream commit).
