# Ficus's pi 1.5.0 patch sources

Upstream release: `earendil-works/pi` at `f9a26365568127461c47a07a37dcb42c140a3ac5` (`v1.5.0`).

Pi 1.5 port: the ten overlays were three-way merged from the 1.4.0 overlays against upstream v1.5.0 with no conflicts, and no Ficus change was absorbed upstream, so every patch is retained. Upstream 1.5 changes inside the overlaid files are kept as-is: summaries skip pre-resolved credentials for runtime-resolving stream functions (`markRuntimeStreamFunction`), tool loadouts keep active-tool order, the read tool passes advisory range hints to `ReadOperations.readFile`, extensions import pi-ai through the new `pi-ai-extension-view` (reached through the virtual modules this loader overlay uses), session paths compare with `pathsEqual`, forks write through one descriptor, and `_appendEntry` now rolls the in-memory entry back when the disk append throws. That rollback does not make `getEntries()` a durable receipt (see below), so `getPersistedEntries()` stays. `agent.ts` and `output-accumulator.ts` are unchanged upstream, and the agent-core patch is byte-identical to the 1.4.0 one.

The nine coding-agent TypeScript overlays preserve Ficus's session event sanitization and persistence ordering, SDK exports, read-tool behavior, bash full-output handling, and host-provided extension module resolution. They were three-way merged from the 0.99.1 overlays against the new upstream source. Pi 1.4 moves initial message construction into `_prepareRun`; the host delivery identity follows that path without exposing it to extension hooks or model content. Its new run-start abort handling is retained after sanitization. Upstream 0.99 added nested tool-call recording (`ctx.executeTool()`) at the top of `_handleAgentEvent`; the merge runs Ficus's sanitizer first, so the nested-call bookkeeping, extension emission, listener emission, and persistence all see the sanitized event. Ficus's `session_message_persisted` emission stays on top of upstream's entry-ID bookkeeping. The extension-loader merge keeps upstream's new MCP server and virtual-model registration APIs while retaining Ficus's host-module fallback for unbundled artifacts. It also always loads jiti's static entry: upstream switched non-embedded runtimes to jiti's lazy entry, which loads Babel from a path relative to jiti's own file (`../dist/babel.cjs`) that does not exist once Core's `bun build` bundles the SDK, so TypeScript extensions failed to load in Ficus artifacts.

The delivery-correlation overlay adds optional `deliveryId` host options to `prompt`, `steer`, and `followUp`. A private WeakMap follows the exact user-message object (including sanitizer replacements); identity is neither extracted from content nor placed on the model message. `SessionManager.appendMessage` atomically includes the optional ID on the same JSONL message entry, and `session_message_persisted` reports it with `entryId`. Existing signatures remain compatible and public barrels are preserved. The additional `session-manager.ts` overlay and its four generated outputs are included in the regeneration allowlist. Upstream already writes a session file starting with the first user message, before a model response.

The bash-tool overlays (`tools/bash.ts`, `tools/output-accumulator.ts`) add an opt-in `persistFullOutput: false` bash tool option. Upstream writes output beyond the display limit, raw, to `os.tmpdir()/pi-bash-<id>.log` (created exclusively with `wx` and owner-only `0o600` permissions, never deleted) and points to it in the result. With the option off, nothing is written to disk: the accumulator keeps the complete output up to the 1 MiB `structuredContent.output` limit and, past it, only the first and last 512 KiB in memory (the same head, omission marker and tail upstream reads back from the file), and results name no full output path. The default stays upstream's. Core's bash tools turn it off, because the file holds stored secrets unredacted on the Core host, where sandboxed agents cannot reach it anyway. pi's interactive/RPC `executeBash` (`bash-executor.ts`) writes the same files but Core never calls it.

`getPersistedEntries()` is the read-only recovery receipt view: it re-reads complete JSONL records from disk rather than trusting `getEntries()` (which upstream mutates before a filesystem append can throw). Missing files and failed directory targets have no receipts; other read failures propagate. The verifier never repairs a partial tail. On ordinary SDK reopen, an unterminated host `deliveryId` entry is discarded at its exact byte boundary, not promoted into a receipt by upstream's newline repair; legacy EOF repair remains unchanged. In-memory sessions intentionally have no durable receipts.

Regenerate from a clean checkout of that upstream commit:

```sh
PI_MONO_DIR=/path/to/pristine/pi bun run patch:pi-coding-agent --write
```

Omit `--write` to verify the committed patch without changing it. Node.js 22.19 or newer and Bun are required. CI uses Node 24. Run `bun install` in this repository first: the sanitizer dataflow gate needs the TypeScript 5 compiler API from the root `node_modules`.

The script installs with the build-only `bun.lock` here and lifecycle scripts disabled. This lock was migrated by Bun (`bun pm migrate`, with `configVersion` kept at 0 as before) from upstream's v1.5.0 `package-lock.json` and pins the isolated build dependencies explicitly, including upstream's compiler pin (TypeScript 7.0.2; 0.99 replaced the TypeScript native preview and `tsx`). Disposable-clone package scripts use Bun in place of upstream's recursive npm calls; application manifests are not changed by regeneration.

The checks require pristine source outputs to match the verified published package, both independent overlay builds and patches to be byte-identical, sanitizer dataflow to pass, and all files outside the output allowlist to remain unchanged. The patch applies to the unbundled SDK used by Ficus, not pi's standalone CLI bundles.

The separate pi-ai patch retains the two hard-plan-limit retry classifiers (upstream 1.5.0 has not absorbed them; the upstream subscription-sharing and Zhipu 1308 classifiers are retained alongside our hard-limit classifiers) and the Claude subscription credential refusal. Keep the refreshed upstream model catalog intact.

The queue-control overlay in `packages/agent/src/agent.ts` adds a public `updateQueuedMessage` operation. It serializes edits, pauses consumption while the host transaction commits, leaves the queue intact on failure, and refuses already-drained messages. Moves retain an out-of-band FIFO key and the original message object, including images. `AgentSession.updateQueuedMessage` resolves host delivery IDs and refreshes its queue display; these IDs and ordering keys never enter model content. The additional agent-core patch is built twice and checked against its published package with an exact four-file output allowlist. Clear-all refuses an in-flight queue edit before changing either SDK queue or display state.
