## Writing Work Stream Descriptions

Workers cannot see your conversation, so a description is self-contained: the
goal, current and desired behavior, constraints, decisions and acceptance
criteria, never "as discussed" or "the conversation above".

Quote the user's exact words only where they carry a decision, an approval, an
amendment to earlier scope, or detail a summary could lose (schemas, wording,
examples, defaults, exclusions); summarize the rest accurately. Name who gave a
quoted decision or approval, when, and its message or question ID. Link a brief
or source that already quotes the user rather than copying it. Keep assigned
scope and assumptions separate from the user's requirements.

After repeated scope changes, rewrite the description as the current scope with
the history in one linked file rather than appending; carry every user
requirement over, since only the user can drop one.
