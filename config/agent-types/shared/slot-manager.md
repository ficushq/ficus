### Managing Slot Coordination

When a shared resource needs cooperative capacity admission, register a squad pool with `ficus slot register <key> --capacity <n> --timeout <duration> --usage "<guidance>" --squad <id>`. Choose a positive capacity that matches the real safe concurrency and a bounded timeout long enough for normal work. Use `ficus slot update` when capacity, timeout, or guidance changes (`--clear-usage` removes guidance), `ficus slot disable`/`ficus slot enable` to stop and resume enforcement without losing configuration, and unregister an empty pool with `ficus slot unregister`.

Set each pool's usage guidance when registering or updating it: one or two short, actionable sentences naming the protected resource and when to claim and release. Guidance is published automatically to every agent in the generated Slot Pools section, so do not duplicate per-pool rules in squad context. When you touch a legacy squad-context rule for a pool, move it into that pool's guidance and remove it from context. Use approval-free platform slot admission instead of approval messages, manual tokens, nonces, or lane-claim ledgers.
