# Configuration

How a ficus instance is configured: the `.env` file, the environment variables it
holds, and how humans and machines authenticate against the API.

`bun run setup` writes most of this for you — see
[docs/wiki/setup.md](setup.md#what-it-writes) for the keys it manages and when it
replaces them. This page is the reference for everything else.

## Config files

```bash
cp .env.example .env
cp ecosystem.config.example.js ecosystem.config.js
```

`.env` holds the instance configuration; `ecosystem.config.js` is the pm2
process file for `tau-api` and `tau-worker` (or `tau-<label>-api` /
`tau-<label>-worker` on a labelled instance — `bun run setup` generates it from
the example with those names substituted in). Both are gitignored.

**Provider API keys:** AI provider credentials (Anthropic, OpenAI, Google, etc.)
are managed from the web UI (**Settings > AI Providers**), or with
`ficus provider-auth set <provider> <key>` for an API key (`list`, `get`, `delete`
and `oauth-providers` round out the command). OAuth logins for ChatGPT Plus/Pro
and GitHub Copilot subscriptions are web-UI only. Anthropic takes an API key
only: Anthropic does not permit third-party products to use Claude Pro/Max
logins, so Core refuses subscription tokens (`sk-ant-oat…`) and deletes any
stored one at startup. This requires
`FICUS_ENCRYPTION_KEY` — without it the page fails with
`Cannot mutate secrets: FICUS_ENCRYPTION_KEY not configured`. Generate a key with
`echo "FICUS_ENCRYPTION_KEY=$(openssl rand -hex 32)" >> .env`.

## Authentication

Ficus uses accounts and passkeys, with user permissions, browser sessions, and revocable CLI/mobile device tokens. `bun run setup` writes a random `FICUS_PASSWORD` for first-admin bootstrap. Sign in with that password and register the first administrator's passkey; once an admin holds a passkey, password login and password bearer authentication are rejected.

A bare local installation without `FICUS_PASSWORD` allows first-user registration without the bootstrap-password gate. It does not make protected API routes public, and clearing the variable does not disable established account authentication. Password mode remains available if admin records exist but no admin has a passkey, for example after a restore that removed credentials.

Browser login sets an HttpOnly session cookie. Browser WebSockets use a short-lived, single-use ticket. CLI and other API clients send bearer credentials. Webhook ingress uses provider signature verification; authenticated management endpoints still require permissions. See [core-auth.md](core-auth.md) for the complete model and [docs/wiki/setup.md](setup.md#first-admin) for first-run instructions.

### CLI authentication

After registering your account, authorize a revocable CLI device token in the browser:

```bash
ficus auth login local --api-url http://localhost:3000
ficus auth status
ficus auth introspect
```

Login stores the backend and its device credential locally; **Settings → Paired Devices** can revoke it. `ficus auth logout local` revokes the device token and removes the local backend. `--local-only` removes local credentials without server revocation.

The CLI still supports an explicitly supplied bearer credential and bootstrap `FICUS_PASSWORD` from the environment or a `.env` found by walking up from the current directory. Those password paths only authenticate while no admin has a passkey. An explicit `--password` or shell `FICUS_PASSWORD` selects credential-based login instead of browser authorization; clear a stale shell password before using browser login. Use `ficus auth status` to inspect the active credential source.

## Integration credentials and optional services

Connect GitHub through **Settings → Integrations → GitHub**, install the GitHub App on the required repositories, and select or inherit the account in the squad's **Integrations** settings. Account connection alone does not grant repository access. Legacy `GITHUB_USER`, `GITHUB_TOKEN`, `GH_TOKEN`, and per-squad token-secret settings are retired; reconnect historical configurations. Git author name/email overrides remain separate under **Settings → Git**. See [GitHub account connections](github-integrations.md).

Agent-model accounts belong to **AI Providers**. **Integrations → OpenAI API services** supplies Realtime voice, audio transcription, and embeddings independently of ChatGPT/model accounts. **Assistant & Memory** controls the Voice assistant, Voice dictation, and Semantic memory search features and exposes the same API-service connection. For services-only setup, use the integration card rather than exporting `OPENAI_API_KEY`, which retains legacy model-provider discovery behavior.

**Integrations → Google Cloud** supplies message read-aloud through Google Text-to-Speech. Configure service-account JSON there, or set the server's `GOOGLE_APPLICATION_CREDENTIALS` path for Application Default Credentials; the integration must be enabled in either case. This is separate from the Assistant's OpenAI Realtime conversation. API-service and Google speech credential changes apply to new requests without a restart.
